# Telegram-боты для команды разработчиков

Набор Telegram-ботов для удобной работы с Merge Requests в GitLab: от назначения ревьюверов и командных напоминаний до просмотра diff и обсуждения изменений с LLM.

В репозитории собраны два инструмента:

- **Командный бот** — помогает организовать ревью и следить за открытыми MR.
- **Личный ассистент** — позволяет работать с MR и получать советы по коду прямо в Telegram.

## Командный бот

Автоматизирует повседневные задачи, связанные с code review.

### Возможности

- Распознаёт ссылки на Merge Requests в сообщениях Telegram.
- Назначает ревьюверов с учётом правил одобрения GitLab и Code Owners.
- Учитывает доступность разработчиков и временные исключения, например отпуск.
- Позволяет запланировать автоматическое возвращение разработчика в список ревьюверов.
- Показывает незавершённые MR и напоминает о них команде.
- Ведёт статистику MR за день, месяц и год.
- Сообщает о проблемах с проверками pipeline.
- Поддерживает интеграцию с Jira для уведомления о приоритетных задачах.
- Может выполнять ИИ-ревью diff и публиковать результат отдельным обсуждением в GitLab.

### Управление через Telegram

В меню доступны управление списком разработчиков, просмотр расписания уведомлений, настройки логирования и режим разработки.

Основные команды:

| Команда | Назначение |
| --- | --- |
| `/start`, `/help` | Меню и справка |
| `/chatid` | ID текущего чата |
| `/mrcount` | Статистика Merge Requests |
| `/mrinfo` | Список незавершённых MR |
| `/jobs` | Запланированные уведомления |
| `/all текст` | Упоминание активных разработчиков |

### Пример использования

1. Разработчик отправляет ссылку на MR в командный чат.
2. Бот проверяет состояние MR и правила одобрения.
3. Выбирает доступных ревьюверов и назначает их в GitLab.
4. Публикует результат в Telegram.
5. При включённой интеграции с LLM запускает дополнительное ИИ-ревью.

## Личный ассистент

Помогает выполнять отдельные действия с Merge Requests из личного чата в Telegram.

### Возможности

- Запросить diff выбранного MR.
- Посмотреть изменения перед ревью.
- Отправить аппрув в GitLab.
- Оставить комментарий к MR.
- Передать diff в LLM и задать вопрос об изменениях.
- Получить объяснение кода, рекомендации или дополнительное мнение перед принятием решения.

### О чём можно спросить LLM

- «Что изменилось в этом MR?»
- «Какие пограничные случаи стоит проверить?»
- «Может ли это изменение повлиять на существующее поведение?»
- «Какие тесты помогут проверить эту логику?»
- «Есть ли здесь более простой способ решить задачу?»

Ответ LLM помогает подготовиться к ревью. Окончательное решение об аппруве и публикации комментариев принимает разработчик.

## Интеграции

- **Telegram Bot API** — команды, меню и уведомления.
- **GitLab API** — Merge Requests, diff, ревьюверы, аппрувы и комментарии.
- **Jira API** — дополнительный контекст о задачах для командного бота.
- **OpenAI-совместимый API** — анализ изменений и ответы LLM, в том числе через локальный сервер моделей.

## Настройка и запуск

Инструкции по установке, переменные окружения и способы запуска описаны в документации каждого бота.

Для работы понадобятся:

- токены Telegram-ботов;
- адрес GitLab и токены с правами на необходимые операции;
- ID чатов и настройки доступа;
- адрес и модель LLM, если используются функции ИИ;
- настройки Jira, если нужна интеграция с задачами.

Секреты задаются через переменные окружения или локальные `.env`-файлы. В репозитории должны храниться только примеры конфигурации без действующих токенов и персональных данных.

## Работа с LLM

При использовании ИИ содержимое diff и сопутствующий контекст передаются настроенному серверу моделей. Выбирайте сервер с учётом правил доступа к коду вашей команды.

LLM может ошибаться и располагает только переданным контекстом. Её рекомендации дополняют ручное ревью, тесты и проверки CI.
