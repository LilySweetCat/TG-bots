# Merge Request Telegram Bot

Telegram-бот на TypeScript для команд, которые проводят ревью в GitLab. Назначает
ревьюверов по ссылкам на Merge Requests, учитывает отпуска и Code Owners, напоминает
о незавершённых MR и ведёт счётчики. Интерфейс и сообщения — на русском языке.

Дополнительно поддерживает Jira и локальный OpenAI-совместимый сервер для ИИ-ревью
и коротких реплик в Telegram. Персональные обработчики и упоминания сотрудников
из исходной версии удалены.

## Быстрый запуск

Требуется Node.js 22 или новее и npm. Команды выполняются из корня проекта:

```powershell
Copy-Item .env.example .env
npm ci
npm run build
npm start
```

Перед запуском заполните `.env` в корне проекта. Команды npm выполняются из корня;
переменные окружения имеют приоритет над значениями в `.env`.
Для разработки используйте `npm run dev`; для проверки типов — `npm run typecheck`.

## Настройки

В [.env.example](.env.example) находятся только пустые значения и публичный
домен-пример. Секреты и настройки вашей команды задаются локально.

| Переменная | Назначение |
| --- | --- |
| `BOT_API_KEY` | Токен Telegram-бота от BotFather, обязателен |
| `GITLAB_URL` | Адрес GitLab, например `https://gitlab.example.com`, без `/api/v4` |
| `GITLAB_ACCESS_TOKEN` | Токен GitLab со scope `api` и правами чтения MR и назначения ревьюверов |
| `ADMINS` | JSON-массив числовых Telegram ID администраторов, по умолчанию `[]` |
| `OWNER_ID` | Telegram ID получателя служебных уведомлений и предложений |
| `TG_TEAM_CHAT_ID` | ID командного чата; в нём учитываются MR и назначаются ревьюверы в GitLab |
| `SERVICE_CHAT_ID` | ID служебного чата |
| `DEV_CHAT_ID` | ID чата для режима разработки |
| `DB_PATH` | Каталог JSON-данных, по умолчанию `./bd` относительно рабочей директории |
| `TZ` | Часовой пояс расписания и вечерних сообщений, по умолчанию `UTC` |
| `SOCKS5_CONNECTION` | Необязательный URL SOCKS5-прокси для Telegram |
| `JIRA_URL`, `JIRA_TOKEN` | Необязательные адрес REST API Jira и Bearer-токен |
| `MR_MOTIVATION_MESSAGE_COUNT` | Период мотивационных сообщений по количеству MR, по умолчанию `12` |
| `MR_CHANGES_COUNT` | Порог сообщения о большом MR, по умолчанию `12` файлов |
| `DISABLE_MISSING_REVIEWERS_MESSAGE` | `true` отключает сообщение об отсутствии ревьюверов; по умолчанию `false` |
| `AI_URL` | Адрес OpenAI-совместимого API с `/v1`; пустое значение отключает ИИ |
| `AI_TOKEN` | Необязательный токен сервера ИИ |
| `AI_MODEL` | ID модели; если пусто, выбирается первая из `GET /models` |
| `AI_TIMEOUT_MS` | Тайм-аут ИИ-ревью, по умолчанию `180000` мс |
| `AI_MAX_DIFF_CHARS` | Лимит размера diff, по умолчанию `60000` символов |

Заполните ID командного, служебного и личного чатов до рабочего запуска. Команда
`/chatid` помогает узнать ID чата. Бот должен иметь доступ к указанным чатам.
В GitLab учитываются правила с именами `lead`, префиксом `Check MR` и типом
`code_owner`; настройте их для своего проекта.

Проверка TLS-сертификатов GitLab включена. Для внутреннего центра сертификации
можно передать доверенный сертификат через `NODE_EXTRA_CA_CERTS`.

## Использование

- `/start`, `/help` — меню и справка.
- `/chatid` — ID текущего чата.
- `/mrcount` — счётчики за день, месяц и год.
- `/mrinfo` — незавершённые MR.
- `/jobs` — запланированные уведомления.
- `/all текст` — упоминание активных разработчиков.

Через меню администраторы добавляют разработчиков в формате
`@TelegramNick GitLabNick`, удаляют их, исключают на время отпуска и возвращают
в список. Доступны календарь автоматического включения, режим разработки,
управление логированием и отправка предложений владельцу бота.

Отправьте ссылку на MR в чат. Бот проверит статус MR и правила одобрения,
выберет доступных ревьюверов и обновит назначение в GitLab для командного чата.
Поддерживаются обычные и скрытые Telegram-ссылки, параметры URL и якоря.

## ИИ

Пример для LM Studio: `AI_URL=http://localhost:1234/v1`. Для Ollama можно использовать
`http://localhost:11434/v1`. В Docker укажите адрес, доступный из контейнера;
на Docker Desktop обычно подходит `host.docker.internal`.

ИИ-ревью публикуется отдельным обсуждением в GitLab. Черновики, WIP, закрытые и
влитые MR пропускаются. Маркер SHA защищает от повторной публикации после
перезапуска. Если MR изменился во время проверки, устаревший ответ не публикуется.
Для проверки новых коммитов отправьте ссылку повторно. Запускайте один экземпляр
бота для одного токена: объединение одновременных запросов действует в одном процессе.

Модели передаются diff, заголовок и описание MR. При сокращённом diff результат
помечается как частичный. Модель не получает весь репозиторий и не запускает тесты.
Ошибки ИИ не должны мешать обычному назначению ревьюверов.

Тот же сервер может создавать короткие реплики бота. При обращении к боту ему
передаются до 1000 символов текущего сообщения, без истории чата. Для реплик
тайм-аут ограничен 8 секундами; при ошибке используется локальная заготовка.
Ссылки, статусы, имена ревьюверов и значения счётчиков формирует код приложения.

## Данные

Каталог `DB_PATH` создаётся автоматически. Бот хранит в нём JSON-файлы:
`userList.json`, `excludedUsers.json`, `suggestions.json`, `mrCounter.json`,
`developmentMode.json`, `mergeRequests.json` и `scheduledJobs.json`.
Новый экземпляр начинает с пустого списка; добавьте разработчиков через меню.
Для сохранения данных контейнера используйте volume и делайте резервные копии.

## Проверки и структура

Из корня проекта:

```sh
npm run typecheck
npm test
```

Тесты собирают TypeScript и проверяют выбор Code Owner, разбор ссылок,
публикацию ИИ-ревью, защиту от дублей и устаревших ответов, повтор после ошибки,
резервные реплики и экранирование HTML. Реальные Telegram, GitLab, Jira и модель
в тестах не вызываются.

- `src/index.ts` — обработчики Telegram, назначение ревьюверов, JSON и расписание.
- `src/types/` — типы данных приложения и декларации сторонних модулей.
- `src/review/` — выбор Code Owner и тесты.
- `src/ai/` — ИИ-ревью, реплики и тесты.
- `src/clients/` — HTTP-клиенты GitLab и Jira.
- `src/utils/` — вспомогательные функции.
- `src/constants/` — константы, настройки календаря и общие сообщения.
- `package.json`, `package-lock.json`, `tsconfig.json`, `.prettierrc.json` — настройки и зависимости в корне проекта.
- `dist/` — результат сборки, исключён из Git; `src/` содержит только исходники и тесты.

Миграция сохраняет совместимость с динамическими ответами API и существующими
JSON-файлами. `noImplicitAny` и `strictNullChecks` пока отключены; полной строгой
типизации всех Telegram-обработчиков и проверки схем JSON на входе ещё нет.

## Docker и Kubernetes

Из корня проекта:

```sh
docker build -t merge-request-bot .
docker run --env-file .env -v merge-request-bot-data:/app/bd merge-request-bot
```

Образ собирается в два этапа на Node.js 22 и запускается от пользователя `node`.
`.env` не копируется в образ. `Dockerfile_example` содержит пример сборки того же
образа; для его использования передайте `-f Dockerfile_example` в `docker build`.

`merge-request-frontend.yaml` — пример Deployment с одной репликой и PVC.
Замените имя образа на адрес своего registry, создайте Secret
`merge-request-bot-env` из локального env-файла и проверьте наличие StorageClass
в кластере. Бот использует long polling, поэтому HTTP Service ему не требуется.
